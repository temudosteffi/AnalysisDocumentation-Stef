cBuildCapEnrolls.vb – Detailed Class Flow and DB Evidence

Scope: This report analyzes only the class cBuildCapEnrolls from the selected VB file. It does not rely on other project files or external classes unless they are referenced by name within this file.

1) Input that comes into the class

  • Constructor receives:
    • sess as Q.Global.IQcsiSession
    • procLog as Q.ProcessLogWrapper.cProcessLog
    • pHeaderId as String
    • pDetailID as String
    • mXML as String
  • The constructor stores those values into class members such as Session, lProcessLog, lDetailId, lHeaderId, and createCAPXML.
  • ProcessMessage(ByRef lxml As String) then creates a new XMLAdvCap and calls InitXML(lxml). This is the main XML message input used for the cap run.
  • Key message fields read from the XML include:
    • m_XMLMessage.programid
    • m_XMLMessage.capdate
    • m_XMLMessage.recondate
    • m_XMLMessage.affiliateid
    • m_XMLMessage.eligibleorgid
    • m_XMLMessage.isGlobal
    • m_XMLMessage.isSummary
    • m_XMLMessage.capitationType
    • m_XMLMessage.advreconrun
    • m_XMLMessage.affils
    • m_XMLMessage.loginfo
    • m_XMLMessage.detailid
    • m_XMLMessage.messagequeueid
  • The class also holds runtime state for many data collections: m_enrollments, m_programCaps, m_openpayments, m_globalcapdata, m_affils, m_policycopays, and the payment queue variables.

2) End-to-end execution chain from the first method to the end

  1. ProcessMessage(lxml)
    • Initializes the XML message.
    • Checks whether the message is a restart run with m_XMLMessage.restarting = "Y".
    • If restart: calls RestartFailedCapRun().
    • If not restart: calls BuildCapEnrolls().
  2. BuildCapEnrolls()
    • Reads CAP batch size option from session.
    • If summary global messages exist, it forces recondate = capdate and reviewdate = capdate.
    • Calls LoadProgramcaps().
    • Walks the loaded program caps and, if usetruecap = "Y", changes the cap date to the last day of the month.
    • Calls LoadOpenPayments().
    • Chooses either Build_Global_Enrollments() or Build_PCP_Enrollments().
    • Calls ValidateCapFactorProgramFundsForAffiliations().
    • Calls ProcessEnrollments().
    • Logs completion and returns true.
  3. Build_PCP_Enrollments()
    • Prepares the first day of the month.
    • Runs CheckPayHolds().
    • Creates a message queue ID.
    • Determines management cap flag from capitationType.
    • Calls the stored-procedure-based query class to load enrollment batches:
    • Either cExecuteSpq_buildpcpcapmessagewithtypeadvreconrun or cExecuteSpq_buildpcpcapmessagewithtype.
  4. Build_Global_Enrollments()
    • Computes l_firstdayofcapmonth.
    • Loads global affiliations via cSelectGlobalAffiliationsByProgramidCapdateRecondateEtc.
    • Validates that exactly one unique global pay-to affiliation exists.
    • Loads global contract data via LoadGlobalContractData().
    • Generates a queue ID.
    • Calls global cap message execution query class cExecuteSpq_buildglobalcapmessage or the advance recon version.
  5. ValidateCapFactorProgramFundsForAffiliations()
    • Extracts the affiliation list from the XML filter string via getAffiliationList().
    • Calls cSelectContractinfoEtcByRequestidlistlistProgramidCapdateEtc.LoadData(programid, capdate, affils).
    • Writes a warning process-log state when an invalid fund is found for a cap factor.
  6. ProcessEnrollments()
    • Uses the loaded m_enrollments.QTable.
    • Groups rows by capmessagequeueid.
    • For each queue, loads default XML data from programcaps/open payments/global contract/global affiliation.
    • Creates a payment record by calling CreatePayment().
    • If caps require adjustment, calls CalcCapAdjustments().
    • Dispatches work synchronously or through the cap batch proxy depending on how many rows are in the batch.
  7. RestartFailedCapRun()
    • Loads remaining cap messages by queue ID via cSelectRemainingCapmessagesByMessagequeueid.
    • If no remaining enrollments exist, finalizes payment via cCapPayment.ProcessMessage(m_OriginalXML).
    • If remaining enrollments exist, re-submits the batch messages.

3) Detailed function-by-function business logic

ProcessMessage(ByRef lxml As String)

This is the public entry method. It does the following:

  • Creates and initializes the XML message object.
  • Sets m_OriginalXML.
  • Sets m_loginfo = (Trim(m_XMLMessage.loginfo) = "Y").
  • If the message indicates restart, calls RestartFailedCapRun().
  • Otherwise, logs start-state entries and calls BuildCapEnrolls().
  • In the final block, it updates the process detail status to completed or error based on the count returned from cSelectProcessstateFailureCountByDetailId.

BuildCapEnrolls()

This is the main orchestration method for the cap run.

  • Sets Opt_CAPBatchSize and reqCAPSize from session options.
  • If the message is summary global, it overrides the recon and review dates to the cap date.
  • Loads program caps and, for any matching cap record where usetruecap = "Y", it moves the cap date to the last day of the month.
  • Loads open payments for the program, affiliate, and type.
  • Chooses global vs PCP flow and then validates cap factors/funds.
  • Processes all enrollment batches and logs final 완료/accepted state.

ValidateCapFactorProgramFundsForAffiliations()

This is a validation check introduced for fund configuration issues.

  • Builds an affiliation list by stripping the parenthesized IN clause from the XML filter string.
  • Calls a query class that checks for invalid fund definitions related to cap factors in the current program and cap date.
  • If any rows are returned and fundid is not empty, it logs a warning with the program, affiliation, factor value, and cap date.

getAffiliationList(ByVal pList As String)

This helper converts a string such as:

"affiliationid IN ('QMQC00000003353','QMQC00000003352')"

into:

'QMQC00000003353','QMQC00000003352'

It does this by finding the first ( and first ) and extracting what sits between them.

Build_PCP_Enrollments()

Builds the enrollment result set for PCP-based capitation runs.

  • Determines the first day of the month.
  • Calls CheckPayHolds() before preparing the message queue.
  • Creates a queue ID and stores it in m_XMLMessage.messagequeueid.
  • If m_XMLMessage.capitationType = "MGT", it translates this to ismanagementcap = "Y"; otherwise "N".
  • Checks whether it is an advance recon run by reading cSelectcapadjustmentReconDateforAdvanceReconRun.
  • Loads the actual enrollment dataset using one of the SQL-procedure query wrappers with a large parameter list including program, cap date, recon date, first day, affiliate, queue id, detail id, eligibleorgid, capitation type, management flag, reqCAPSize, and optional advance recon date.

Build_Global_Enrollments()

Builds the enrollment result set for global capitation runs.

  • Loads a global-affiliation dataset.
  • Requires a single unique pay-to affiliation to proceed. If not, exception is thrown.
  • Loads global contract data for that pay-to affiliation.
  • Requires at least one contract row; otherwise it throws.
  • Creates a new queue ID and calls the global-cap message stored-procedure query wrapper.

ProcessEnrollments()

This method takes the prebuilt enrollment data and turns it into actual processing work.

  • Uses m_enrollments.QTable and sums EnrollCount.
  • Groups batches by capmessagequeueid.
  • For each queue:
    • Loads program caps, open payments, global contract data, and global affiliation into the XML message.
    • Finds the matching enrollment rows for that queue.
    • Creates a payment using CreatePayment().
    • Calls CalcCapAdjustments() if the cap needs adjustment.
    • Processes as either a single batch or multiple batch messages via CapitationBatchProcessProxy.
The method intentionally logs a state if no enrollments are found, and also logs an error if the dataset itself was not available.

RestartFailedCapRun()

This path is used when the incoming XML says the message is restarting.

  • Loads remaining cap messages using:
  • m_enrollments = New Queries.cSelectRemainingCapmessagesByMessagequeueid(Session)
  • m_enrollments.LoadData(m_XMLMessage.messagequeueid)
  • If count indicates all enrollments are complete, finalizes payment through cCapPayment.ProcessMessage(m_OriginalXML).
  • If work remains, it replays the batch process with the remaining data.

DistinctRateIDSQL()

This helper creates the rateid list used in policy copay queries.

  • It builds a SELECT DISTINCT string from either glob al or PCP logic.
  • It includes a union of active enrollments and prior cap vouchers.
  • It filters by programid, affiliateid, capdate, recondate, and capitation type.

The literal SQL in this method is directly assembled in the file. A shortened evidence block is below:

AND payment.paytype = 'capitationType' ) a JOIN enrollkeys enr ON enr.enrollid=a.enrollid

5) Summary: the real operating flow

  1. Receive cap XML message.
  2. Determine if it is a restart.
  3. For new runs, load program caps and adjust date if needed.
  4. Load open payments.
  5. Choose either global or PCP enrollment generation.
  6. Validate cap-factor/fund setup.
  7. Process raw enrollment batches.
  8. Create payment records.
  9. Apply cap adjustments to vouchers.
  10. Dispatch each batch to the batch processor.
  11. Finalize or continue processing for retry/restart scenarios.

Important: This file does not contain the final implementation SQL for the generated query classes such as cExecuteSpq_buildglobalcapmessage or cRetrieveProgramCapsByProgidCapTypeEffdateTermdate. The class invokes those classes via LoadData(...), but the literal SQL is hidden in their generated query definitions outside this file. The SQL shown above is the exact query evidence that is present in this file itself, and it matches the intended logic being executed.
