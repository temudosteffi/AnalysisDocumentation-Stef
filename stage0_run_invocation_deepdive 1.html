2. Executive Summary

Stage 0 begins a capitation run by collecting run-scoping inputs (e.g., eligible org/sponsor selection, program selection, capitation date, reconciliation options) in the QNXT Administrator web wizard and then submitting those inputs into the QNXT/QFrame “agent” execution infrastructure via proxies. Evidence in this graph confirms the UI wizard pages exist and that downstream provider-level fan-out is performed in the CapitationSetup ASC by building provider lists and sending CapProviderRequestMessageType messages through Q.Proxy.CapProviderProxy. However, several hypothesized Stage-0 components (e.g., CapSubmitAgent, XSLTCapSubmit.xslt, and the PlanIntegration process catalog tables/rows) were not found in the retrieved graph content for this run and remain open questions. c
