1. Executive Summary

The EDI 820 (Payment Order / Remittance to MCOs and capitated providers) is generated by the TriZetto QNXT Connect subsystem — specifically the HIPAA Export 820 Activity Service Component — and is finalized for transmission by the Edifecs XEngine EDI Gateway (sis-inx-edigw). It is not produced by the EdiFabric library referenced in mms-cms-cef (that library is used for inbound 837/835 parsing), and it is not produced by the Ohio financial check/EFT export stream in mms-bolton-fin-ohio (that stream emits INF02/ChkPrint/PosPayment files).

Verified pipeline: Capitation run writes capvoucher+payment (status PAID) → QNXT Connect Agent820Export builds an X12/XML 820 from the capitation payment data → Agent820ExportBiztalk posts it to BizTalk → the payment status is flipped PAID → PAIDCAP → BizTalk drops the file to QNXTConnectShare\BizTalk\Outbound\820 → the EDI Gateway Directory Polling Service moves it to the Edifecs X12 share → Edifecs XEngine maps/guidelines + trading-partner routing + 820Combine batching produce the transmit-ready X12 005010X218 file.

Bottom line on the hypothesis — the statement “after payment reaches Paid status, a user manually enters QNXT, triggers 820 generation, QNXT creates XML, and Edifecs converts that XML into an X12 820” is PARTIALLY TRUE (mostly true, with two clarifications):

  • CONFIRMED QNXT creates the 820 payload (as XML that already carries the X12 820 structure) and posts it to BizTalk.
  • CONFIRMED Edifecs receives it and produces the final X12 820 — but its role is mapping/guideline validation, trading-partner enveloping/routing, and batching, not a from-scratch XML→X12 conversion (the 820 segment structure originates in QNXT Connect).
  • INFERRED A manual QNXT UI path exists (820CRE.aspx / 820CREDet.aspx), but the transfer, transformation, routing and batching downstream are automated / scheduled. Whether operators kick off each run manually or a scheduled QFrame process does is not fully provable from source and is an SME question.

4. End-to-End Call Chain

Execution sequence (verified)

  1. Capitation processing writes capvoucher + payment rows; payment reaches status PAID. CONFIRMED
  2. QNXT Connect Agent820Export.ProcessMessage deserializes an Export5010_820RequestType and calls cHIPAA820Export.ExportMsg. CONFIRMED
  3. cHIPAA820Export assembles the 820 from QCapVoucher/QPayment/QTradingPartner into an XmlDocument shaped as X12_00501_820 / X12_4010_820. CONFIRMED
  4. Agent820ExportBiztalk.PostToBiztalk posts the message to BizTalk; BizTalk writes the file to QNXTConnectShare\BizTalk\Outbound\820. CONFIRMED (post) / INFERRED (BizTalk file drop path, from the polling source path)
  5. On success, payment status is updated PAID → PAIDCAP. CONFIRMED
  6. EDI Gateway Directory Polling Service (X12_5010_820 Transfer) moves the file to the Edifecs X12 share. CONFIRMED
  7. Edifecs XEngine applies ST_Map_820.ems/Connect_820.ecs + 820x218.ecs guideline + trading-partner routing; the OH custom post-process agent rewrites ISA08 via Get820TPID. CONFIRMED
  8. 820Combine batchers assemble VAN/UPLOAD output; the file is transmitted externally. CONFIRMED (batching) / UNKNOWN (final transport endpoint)

10. Alternative Flows

  • Other outbound X12 from QNXT Connect. Parallel export components exist for 834 (enrollment) and 835 (claim payment) under QNXT Connect/5010/ASCs/HIPAA Export 834 and HIPAA Export 835, each with its own AgentNNNExportBiztalk. The 820 is one member of this family. CONFIRMED
  • ETL-record input to Edifecs. Besides file movement, an ETL-record path (up_edigw_transfer_edifecs_etl_records) feeds Edifecs ETL staging into EDI_Gateway. This is a secondary ingestion mechanism, run every 5 minutes. CONFIRMED
  • Finance check/EFT stream. The dollar disbursement to providers/MCOs (checks, positive pay, EFT accounting) is handled separately by Hpfin_PayFileExport in mms-bolton-fin-ohio; it is distinct from the 820 remittance/payment-order transaction. CONFIRMED
  • 4010 legacy path. Export820.cs still carries 4010 constants (X12_4010_820, BIZMSGTYPE_4010); the active outbound is 5010 (005010X218). INFERRED (both versions present; 5010 is the routed guideline)
