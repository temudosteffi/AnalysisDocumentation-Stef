2. Missing or materially underdeveloped concepts

2.0 Complete .sln Inventory

The reference provides a solution-by-solution implementation map that is absent from the AI-tool analysis. The missing inventory is:

  • UI solutions: QNXTALL.sln for the three-page wizard and QTaskScheduler.sln for Windows Task Scheduler COM interop.
  • Legacy Stage 0 agent solutions: CAPSubmit.sln, CapData.sln, CAPGlobal.sln, CapPcp.sln, and SelectCapAffiliations.sln.
  • ASC solutions: QCSI ASC CapitationSetup.sln for CapProgramAgent/CapProviderActivity, QCSI ASC Capitation.sln for the calculation library, and QCSI ASC PostCapitationBatchAgent.sln for configured but inactive post-capitation agents.
  • Payment-layer solutions: QCSI_Capitation.sln for IAdvCap.vb, QCSI Payment DAL.sln, and QCSI Payment Service.sln.
  • Proxy and infrastructure solutions: QCSI Proxy Payment.sln, QCSI Internal Proxy.sln, and DistributionHub.sln, including the proxy routing and Distribution Hub hand-off responsibilities.

2.12 Error handling, observability, and operational risk

  • Missing: UI success/failure message IDs 3715 and 3717 from GenerateMessages().
  • Missing: The partial-submission risk caused by HTTP dispatch iterating messages one by one without rollback or TransactionScope.
  • Missing: The stronger atomicity observation that Service Broker wraps messages in one QEnterpriseEnvelope.
  • Missing: Process-log header creation in STARTED state and the AUDIT-level detail states written by CapProviderActivity.
  • Missing: Legacy-agent catch blocks that only call Console.WriteLine(e.Message), creating a silent/partial failure risk.
  • Missing: The non-idempotency finding: a normal resubmission can create new process-log headers and duplicate provider messages, which explains the separate Restart mode.

2.13 Explicit unresolved questions

The reference explicitly records unresolved areas that the AI-tool document does not preserve as a complete list:

  • Where the deployed Scheduler.exe is built from and whether it is custom or COTS.
  • Where the SQL or stored-procedure implementation behind CPayMgrUI.ProcessRequest is configured.
  • Where GetProgramCapList and BlanketProviderList are implemented in the base class/DAL hierarchy.
  • Whether SQL Agent jobs provide any additional capitation entry point.
  • The numeric/configuration source for optSchedule.

  • Database objects, evidence statements, glossary, and a broad flow diagram.
