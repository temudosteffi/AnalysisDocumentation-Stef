1. Executive Summary

Stage 0 — Run Invocation is the trigger mechanism that initiates a capitation payment calculation cycle. It accepts a user's request specifying which Managed Care Programs to process, for which month (capitation date), with optional reconciliation parameters and provider/affiliation filters. The request can be submitted via the QNXT Administrator Web UI ("Create Capitation Payments" wizard), or scheduled via Windows Task Scheduler using the QTaskScheduler library. Upon submission, the system constructs typed message objects (CapSubmitRequestMessageType), dispatches them through the BulkProxy/OneWayProxy infrastructure (which routes to either the QEnterprise Distribution Hub via HTTP POST, SQL Service Broker queue, or direct agent bypass), and the messages flow through an agent chain: CapProgramAgent → CapProviderActivity.BuildProgramCapitation() → provider list construction → XSLT fan-out per-provider — producing per-provider CapProviderMessage payloads that hand off to Stage 1 (Calculation).

11. Parameters & Message Schema

11.1 CapSubmitRequestMessageType (Typed Message)

This is the .NET serializable message object constructed by GenerateMessages() and sent through CapSubmitProxy:

CapSubmitRequestMessageType {
    headerId          : string   — Process log header GUID
    detailId          : string   — Process log detail GUID  
    Program           : CapProgramMessageType {
        Id            : string   — Program GUID (from PROGRAM table)
        FundId        : string   — Fund ID associated with program
    }
    Capitation        : CapitationMessageType {
        CapDate       : DateTime — The month being calculated (from txtDate)
        DoGlobal      : YesNoType (Y/N) — Whether to process global providers
        DoRecon       : YesNoType (Y/N) — Whether reconciliation is enabled
        ReconMonths   : long     — Number of months to look back for reconciliation
        ReviewMonths  : long     — Number of review months
        IsCapitatedOnly : YesNoType (Y/N) — Filter to capitated contracts only

17. Glossary

TermDefinition
ASC (Application Service Component)A .NET class library that encapsulates business logic for a specific domain. ASCs are invoked by agents and contain the actual processing code. Example: QCSI ASC CapitationSetup contains CapProviderActivity.
AgentA lightweight .NET class (inherits from QFrameAgent) that receives an XML or typed message, processes it, and optionally routes the result to the next agent in the chain. Agents are the unit of orchestration in QFrame.
BulkProxyInfrastructure base class for dispatching arrays of typed messages to the processing infrastructure. Handles process logging, serialization, and routing (Distribution Hub vs Service Broker vs Direct).
ByPassQEnterpriseA registry-configurable flag. When set, messages skip the Distribution Hub and are processed directly by MessageProcessorEngine in-process. Used for debugging or single-server deployments.
CapitationA payment model where a health plan pays a fixed per-member-per-month (PMPM) amount to providers, regardless of services rendered. The capitation "run" calculates these payments.
Capitation Date (CapDate)The month for which capitation payments are being calculated. Always the first of a month (e.g., 07/01/2026).
CPayMgrUIA service router object that maps named requests (like "LoadCarrierMod") to data access operations. Acts as a facade between UI code and the database.
Distribution HubThe QEnterprise message routing web service. Receives HTTP-posted XML messages and routes them to the appropriate agent chain based on process log type.
Fan-outThe pattern of splitting a single request into multiple independent messages for parallel processing. Stage 0 fans out: 1 request → N programs → M providers per program.
Global Provider (Global Contract)A provider with a "blanket" capitation arrangement — they receive capitation for all members in a program, regardless of PCP assignment.
IQcsiSessionInterface representing an authenticated user session. Carries environment ID, username, and is required for all service calls.
MCP (Managed Care Plan/Program)A specific Medicaid managed care program (e.g., CareSource, Molina). Each MCP has a unique programid in the system.
MessageProcessorEngineQFrame component that processes messages directly by looking up the process chain (from PlanIntegration DB), instantiating the appropriate agent via reflection, and calling ProcessMessage().
OneWayProxyBase class for fire-and-forget single-message dispatch. Used by CapitationBatchProcessProxy. Similar to BulkProxy but for single messages.
PCP (Primary Care Provider)A provider with member-specific capitation — they receive capitation only for their assigned members.
PlanIntegrationThe SQL Server database that stores QFrame process configuration: chains, steps, agents, assemblies, and process execution logs.
Process ChainA configured sequence of agents (identified by logtype) that messages flow through. Example: ADV_CAP_PROC → step 0 = CapProgramAgent.
Process Log TypeA string identifier (e.g., "ADV_CAP_PROC") that maps to a process chain definition in PlanIntegration. Used by proxies to route messages to the correct agent chain.
QFrameThe .NET infrastructure framework underlying QNXT/HealthPAS. Provides message routing, agent orchestration, service components, and proxy patterns.
QNXT / HealthPASThe COTS (Commercial Off-The-Shelf) healthcare administration platform by TriZetto/Cognizant. QNXT is the claims adjudication system; HealthPAS is the broader platform name.
QTaskSchedulerA .NET library providing COM interop with Windows Task Scheduler. Used to create deferred execution tasks for capitation runs.
Reconciliation (Recon)The process of re-calculating capitation for prior months where retroactive changes occurred (new enrollments, terminations, corrections). Controlled by ReconMonths parameter.
Service Broker (SSB)SQL Server Service Broker — a message queuing system built into SQL Server. When enabled, messages are enqueued to a SQL queue rather than HTTP-posted to the Distribution Hub.
XSLTExtensible Stylesheet Language Transformations — XML transformation language used to split/reshape messages in the agent pipeline. Stage 0 uses three XSLT files for fan-out logic.
